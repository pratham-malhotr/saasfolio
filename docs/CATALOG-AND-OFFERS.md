# Expanded SaaS catalog and automatic offer refresh

The [27 October expansion](BRAND-EXPANSION-2026-10-27.md) adds 24 brands and 32 original guides, bringing current available coverage to **763 brands and 102 guides**. The dated counts below describe earlier batches.

See the [mobile performance and page review](PERFORMANCE-AND-PAGE-AUDIT-2026-10-27.md) for the Lighthouse comparison, footer fixes, full-site checks and reconciliation with GitHub's automated offer refresh.

The directory contains 735 canonical profiles, including 244 additions recorded in
`lib/data/brand-expansion.txt`. The existing visual design is preserved. Existing
generated ratings, customer reviews, coupon codes, countdowns, and verification
claims are no longer used as proof of a real discount. The latest [24-brand expansion](brand-expansion-seo.md)
includes an original discount guide for each addition. There are 727 available
profiles and 46 dedicated guides; unavailable providers are excluded from browsing.

## Data and sources

- `brand-expansion.txt` is the editable list of additional brands, with their
  category, official pricing URL, specific description, and product areas.
- `expanded-tools.json` is generated by `npm run catalog:expand`. Prices and
  customer ratings are not invented. Plans with unknown prices link to the vendor.
- `expansion-discount-guides.ts` contains original buying guidance, source dates,
  best-discount comparisons, eligibility and troubleshooting for the latest additions.
- `catalog-seeds.json` records the previous catalog's public source URLs.
- `reviewed-offers.json` defines reviewed coupon/program records, evidence
  assertions, restrictions, destinations, and any actual expiration.
- `offer-snapshot.json` records public-source checks, content fingerprints,
  offer evidence, candidates, errors, and source timestamps. It requires no API
  keys. The first full refresh checked 733 sources; later targeted checks added
  more reviewed records. HTTP failures are recorded as failures.
- `legacy-deal-aliases.json` maps old generated offer slugs and IDs to their
  brands. Old pages permanently redirect to a current canonical offer or pricing
  page. Unknown redirect identifiers return 404.

The public catalog distinguishes vendor offers, third party reported coupons,
and pricing links. Free plans and trials have no invented percentage discount.
An affiliate/referral link alone is not a discount. A source check does not mean
the code has been applied at checkout.

The initial coupons include Hostinger's `COUPONSPAGE`, TechRadar's reported
`TECHRADAR`, and the October Namecheap codes `GHOSTPE`, `GHOSTDOT`, and `GHOSTSSL`.
Namecheap's public coupon page was reviewed manually because direct automated
requests returned 403. These records have a source method, date, and October
expiration; failed automated attempts never advance their checked date.

## Refresh behavior

```sh
npm run catalog:expand
npm run catalog:refresh -- --discovery
npm run validate:catalog
npm run test:offers
npm run build
```

For a small refresh:

```sh
npm run catalog:refresh -- --only=hostinger,notion,github
```

The collector uses six workers, serializes each host, spaces requests, respects
robots rules, supplies a crawler identity, and uses conditional HTTP requests.
It restricts requests to configured public HTTPS sources, limits response size,
and rejects off-domain redirects and browser challenges. It extracts visible
free-plan/trial evidence and checks reviewed offers against their required
evidence. Unknown structured coupon codes become review candidates, not
automatically verified discounts. Failed requests retain the previous source
date; records older than 14 days or past a published expiration stop appearing
as offers. Pages and the sitemap revalidate hourly so aging offers can disappear
even if the scheduled refresh stops. Brands without a current offer fall back to
official pricing links.

To approve a discovered code, check the source and merchant restrictions, then
add a record to `reviewed-offers.json` with exact evidence, destination URL,
eligibility terms, and an expiration when one is published. Run the targeted
refresh and validation before committing. Changed or missing evidence removes
the reviewed offer on a successful fetch; a fetch error is recorded separately.

## SimplyCodes and REA investigation

The requested [REA repository](https://github.com/morluto/rea) describes a toolkit
for inspecting application behavior. Its setup installs agent/MCP configuration
and requires restarting the agent; it is not an embedded coupon feed. No REA
agent/MCP configuration change or private SimplyCodes integration is claimed here. A later investigation ran the version-pinned REA CLI in a temporary cache; see [the REA investigation and implemented adapter](research/simplycodes/README.md).

SimplyCodes' public store pages expose offer descriptions, reported usage and
verification activity, and merchant links. The public
[robots rules](https://simplycodes.com/robots.txt) disallow API, redirect, AJAX,
and verification routes. The implementation uses public store URLs only. Direct
requests returned 403 in this environment, so no codes were recovered through
its private endpoints or challenge circumvention. Public research links remain
available on matching brand profiles. Accessible TechRadar and vendor pages
provide other sources. Discovery adapters can inspect explicit structured
promotion codes when a public page supplies them; hidden reveal buttons are not
treated as evidence of a code's value.

## Scheduled operation and deployment

`.github/workflows/refresh-offers.yml` runs twice daily and supports manual runs.
It refreshes sources, validates data, tests the collector, builds the site, and
commits the snapshot only after checks pass. It uses the repository's
`GITHUB_TOKEN` with `contents: write`; it needs no external secrets. Publishing
this branch to GitHub and enabling Actions are required before it runs.

Connect the host serving saasfolio.tech to deploy catalog commits, or run the
same commands in its scheduled deployment pipeline. A snapshot commit alone does
not certify that the public site has deployed. Workflows triggered by the
default GitHub token do not start other GitHub push workflows; use a configured
deployment hook or GitHub App when the deployment relies on such a workflow.

## SEO behavior and validation

The 12 category pages reuse the current deals interface and contain unique
category metadata, real counts, crawlable offer links, and collection schema.
The homepage category cards link directly to these pages. Profiles and offers
have distinct metadata; unproven claims such as “tested today” and automatic
coupon stacking are removed. Software schema includes product features and
official URLs, without unverified stars or prices. FAQ schema is included only
where the same questions and answers are visible.

The sitemap includes public brand profiles, sourced offers, and categories.
Pricing-only offer pages use `noindex, follow` to avoid duplicating profiles.
Offer modification dates come from recorded evidence changes. Other pages do
not receive invented modification dates on every build. Existing canonical,
social, robots, and site verification settings are preserved.

```sh
npm run start -- --hostname 127.0.0.1 --port 3210
npm run seo:audit -- http://127.0.0.1:3210
```

The production audit checks sitemap pages, metadata, structured data, headings,
links, canonical behavior, noindex responses, and actual redirect headers. The
collector tests cover robots exclusions, challenges, unsafe URLs, exact offer
destinations, stale-offer fallback, and legacy aliases. Submit the deployed
sitemap in Search Console using the steps in `docs/SEO.md`; search ranking and
indexing are controlled by the search engines.
